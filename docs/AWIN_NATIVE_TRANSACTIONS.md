# Native Awin transaction adapter
Owner-attested import of the native legacy publisher transactions response JSON array, not a new-generation API or a CSV export. Source: https://help.awin.com/apidocs/returns-a-list-of-transactions-for-a-given-publisher and legacy sample https://success.awin.com/articles/en_US/Knowledge/Publisher-API-GET-transactions-list. Select a registered authorized Awin advertiser. Use a UTC response, actual observation/statement date, stable statement reference, at most 100 transactions and 100 KB per uploaded file. The pure adapter also supports bounded 1 MB input for future server retrieval. Input must contain exact publisher/advertiser/transaction IDs, transactionDate, commissionStatus, commissionAmount.amount/currency and paidToPublisher. Unsafe numeric IDs, unknown statuses, contradictory payment flags, non-USD, negative or sub-cent amounts, invalid dates and duplicates fail closed. Approved plus explicit paidToPublisher=true maps to reported paid, not bank receipt. Declined/deleted with explicit unpaid maps to zero eligible commission (ledger reversed status), regardless of reported original commission. Other fields including orderRef, clickRefs, IP hash, country and basket products are discarded. No raw response persisted; no network request for upload. Reconciliation reuses migration 029 and its owner authorization, observations, duplicate/older statement safeguards. No real API response or signed-in browser verified yet. Same-day conflicting observations require explicit resolution; not silently rewritten. No scheduled API pulls or payment settlement reconciliation enabled.
